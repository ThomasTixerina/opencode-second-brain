## 🚨 Bloqueo Crítico — Flet no renderiza en Windows

### Síntoma
Pantalla blanca en ambos modos:
- **WEB_BROWSER**: Sesiones se crean y destruyen inmediatamente (garbage collected)
- **FLET_APP (nativo)**: Ventana abre pero no renderiza contenido

### Versiones probadas
| Versión | Resultado |
|---------|-----------|
| 0.85.2 | Pantalla blanca (web + desktop) |
| 0.84.0 | Pantalla blanca (web + desktop) |
| 0.25.2 | API incompatible (`ft.run` no existe) |

### Diagnóstico
1. **App mínima también falla**: `ft.app(main, port=8500, view=ft.FLET_APP)` con solo `page.add(ft.Text('Hello'))` → pantalla blanca
2. **Imports OK**: Todos los módulos importan sin errores
3. **Syntax OK**: 18/18 archivos pasan `ast.parse()`
4. **Server OK**: Uvicorn arranca, WebSocket conecta, HTTP 200
5. **Cliente Flet**: Se descarga e instala correctamente desde GitHub releases
6. **Logs**: No hay Traceback en Python — el crash es del lado del cliente Flutter

### Causa raíz probable
- Flet 0.84+ usa Flutter 3.41+ con CanvasKit renderer
- CanvasKit requiere descargar `canvaskit.js` y fonts de Google CDN
- En Windows, el cliente desktop Flet tiene bugs conocidos con el renderizado
- Issue reportado: [flet-dev/flet#4678](https://github.com/flet-dev/flet/issues/4678) — "blank page on build"
- Issue reportado: [flet-dev/flet#5345](https://github.com/flet-dev/flet/issues/5345) — "WebRender HTML and AUTO do not work"

## 🧠 Aprendizajes

- Flet 0.84+ tiene problemas de renderizado en Windows que no se solucionan con downgrade menor
- El cliente Flet desktop se descarga automáticamente desde GitHub releases
- CanvasKit renderer es el default y requiere conexión a internet para fonts y skwasm
- `ft.run()` reemplazó a `ft.app()` desde v0.80
- Las sesiones Flet se garbage collect si el cliente Flutter crashea durante el renderizado
